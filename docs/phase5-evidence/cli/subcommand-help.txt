=== pokie build --help ===
Usage: build [options] [command] <configPath> [excess...]

Generate a POKIE game package from a GameBlueprint JSON config (reels, symbols,
paylines, paytable) (for a ready-to-run package instead, see "pokie init").
"random"/--random generates a first-class random game instead (--seed to
reproduce it, --preset default|variant to pick the generation strategy).
--dry-run validates and previews without writing anything.

Arguments:
  configPath                    a GameBlueprint JSON config (see
                                docs/cli.md#pokie-build-configjson)
  excess                        rejected if present -- this command takes no
                                further positionals

Options:
  --target <dir>                output directory (default: the generator's own
                                default output directory)
  --dry-run                     validate and preview without writing anything
  -h, --help                    Display help for this command.

Commands:
  random [options] [excess...]  Generate a first-class random game instead of
                                loading a config file.


=== pokie create --help ===
Usage: create [options] [name] [excess...]

Design a Blueprint Project -- a standalone GameBlueprint JSON file (reels,
symbols, paytable, reel weighting) that feeds into "pokie build" -- through an
interactive wizard when run in a terminal with no --blank/--random ("pokie
create <name>" pre-fills the name), or write one straight from the filled-in
starter template non-interactively via --blank for a bare-minimum one, or
--random for an always-valid randomly generated one, with its reel weighting
already expressed as valid per-reel generation (--seed to reproduce it, --preset
default|variant to pick the generation strategy). For a prepared, immediately
valid package instead, use "pokie init".

Arguments:
  name               optional preset name -- pre-fills the wizard, or names the
                     --blank/--random output
  excess             rejected if present -- this command takes no further
                     positionals

Options:
  --blank            write a bare-minimum blueprint straight from the starter
                     template, no wizard
  --random           write an always-valid, randomly generated blueprint
                     directly, no wizard
  --seed <integer>   reproduce a specific random blueprint (only meaningful with
                     --random)
  --preset <preset>  which random generation strategy to use (only meaningful
                     with --random) (default: "default")
  --out <file>       output path (default: derived from the written blueprint's
                     own manifest id)
  -h, --help         Display help for this command.


=== pokie init --help ===
Usage: init [options] [directory] [excess...]

Turn the current or given [directory] into a prepared, immediately valid POKIE
game package in place, with no game-id subdirectory: merges/patches
package.json, and writes tsconfig.json, README.md and a real, hand-editable
src/index.ts wherever they're missing, then (unless --no-prepare) installs
dependencies and builds and verifies dist/index.js -- entirely
non-interactively, with --package-name/--game-id/--game-name/--version to
override its directory-derived defaults. Never asks reel/paytable/mechanics
questions; for those, design a Blueprint Project with "pokie create" and build
it with "pokie build" instead.

Arguments:
  directory              directory to initialize in place (default: the current
                         directory)
  excess                 rejected if present -- this command takes no further
                         positionals

Options:
  --package-name <name>  override the package.json "name" (default: derived from
                         the directory)
  --game-id <id>         override the game manifest id (default: derived from
                         the directory)
  --game-name <name>     override the game manifest name (default: derived from
                         the directory)
  --version <version>    override the initial package/game version (default:
                         "0.1.0")
  --yes                  confirm merging into a non-empty directory that doesn't
                         look like a POKIE package yet
  --no-install           skip "npm install" (still builds/verifies unless
                         --no-prepare is also given)
  --no-prepare           scaffold files only -- skip installing dependencies,
                         building, and verifying
  -h, --help             Display help for this command.

=== pokie sim --help ===
Usage: sim [options] <packageRoot> [excess...]

Run a simulation against a POKIE game package and report RTP/hit-frequency/max
win.

Arguments:
  packageRoot                an existing POKIE game package, or a native
                             outcome-library bundle (with --mode)
  excess                     rejected if present -- this command takes no
                             further positionals

Options:
  --rounds <number>          number of rounds to simulate (default: 1000)
                             (default: 1000)
  --seed <string>            seed for a reproducible simulation (default: a
                             random seed)
  --workers <number>         number of parallel worker threads, 1-32 (default:
                             1) (default: 1)
  --out <file>               write the simulation report JSON to this path
  --format <format>          only "json" is supported (default: a human-readable
                             summary) (default: "summary")
  --mode <betModeId>         bet mode to simulate (default: the game's own
                             default bet mode; or "all" for every declared mode)
  --min-rounds <number>      adaptive convergence: minimum rounds before
                             checking for stability (requires
                             --rtp-tolerance/--check-interval)
  --rtp-tolerance <number>   adaptive convergence: acceptable RTP half-width
                             (requires --min-rounds/--check-interval)
  --check-interval <number>  adaptive convergence: how often (in rounds) to
                             check for stability (requires
                             --min-rounds/--rtp-tolerance)
  --stable-checks <number>   adaptive convergence: consecutive stable checks
                             required (default: 1; requires the other three
                             convergence flags)
  -h, --help                 Display help for this command.

=== pokie fairness --help ===
Usage: fairness [options] [command]

Provably Fair commit-reveal workflow: publish a server-seed commitment, publish
a round commitment against a live outcome-library bundle, reveal the round
proof, and verify a proof against its commitment/bundle ("pokie fairness
seed-commit|commit|reveal|verify").

Options:
  -h, --help                                               Display help for this command.

Commands:
  seed-commit [options] <serverSeedPath> [excess...]       Publish a server-seed commitment (the first step of the commit-reveal scheme).
  commit [options] <serverSeedCommitmentPath> [excess...]  Publish a round commitment against a live outcome-library bundle.
  reveal [options] <commitmentPath> [excess...]            Reveal the round proof once a committed round has settled.
  verify [options] <proofPath> [excess...]                 Independently verify a round proof against its commitment and a live source bundle.
  help [command]                                           display help for command
