## Product contract

Matrices are reel-major: `matrix[reel][row]`, zero-based, with the origin at the generated
matrix's top-left. `ScreenGeometry.generated` explicitly declares integer dimensions.
Windows span every reel; horizontal cropping, per-reel offsets and ragged overscan are rejected.
`visible.rowOffset` and `visible.rows` are continuous geometry in symbol-height units;
`evaluated.rowOffset` and `evaluated.rows` are integer cell bounds. Paylines and calculation
positions are evaluation-local. Neither matrix height nor display clipping enables overscan.

```ts
config.setScreenGeometry({
    generated: {reels: 5, rows: 7},
    visible: {rowOffset: 1, rows: 3},
    evaluated: {rowOffset: 2, rows: 3},
    paylineSpace: "evaluated",
});
```

`getReelsSymbolsNumber()` remains the number of discrete cells represented per visible reel.
With visible offset 1.25 and extent 2.5, those are generated rows 1, 2 and 3, with coverage
0.75, 1 and 0.75. The first cell's visible index is 0, not a fractional cell index. Its original
generated identity remains [reel, 1]. Coverage does not give that cell payout eligibility.
Evaluation rows 2 through 4 remain eligible even if row 4 is outside this viewport.
`ScreenProjection.map(position, from, to)` returns `null` for a valid integer cell outside a
space and throws for malformed indexes. Every represented cell round-trips through its inverse.

The ordinary generator draws one stop per reel, starts generated row 0 at that stop and wraps the
strip as before. It draws all declared generated rows. Overscan does not consume extra RNG draws.
`getSymbolsCombination()` retains generated data; `getVisibleSymbolsCombination()` and
`getEvaluatedSymbolsCombination()` name the two projections. Combination capability methods
carry geometry and space, including the visible projection. Decorators project their own generated
screen so ordinary symbol overlays remain visible. `projectEvaluationSymbols` is the explicit adapter for direct APIs;
config-less value calculation requires a tagged combination to recognize overscan.
No configuration means the existing full matrix, including intentionally ragged variable grids.
Default horizontal lines retain pattern-level awards on ordinary ragged grids, including custom generators without variable-height tags; authored out-of-domain paylines remain errors. Sparse line entries are always malformed. Explicit identity geometry preserves seeded results and omits unnecessary transport/artifact evidence.

Every built-in payout path consumes evaluation-local cells, including line, scatter, ways, cluster,
value and multiplier calculations. Context normalization, payline bounds and returned-position
checks remain mandatory with `validateOnEvaluate=false`. Injected calculators/evaluators receive
an evaluated combination. Their results must obey the same position contract; custom codecs are
not thereby certified for persistence. Free-game grants count evaluation cells independently of
missing, zero or positive monetary scatter awards. Invalid geometry/paylines are checked before
an ordinary direct session debit; rejected calculations expose zero rather than a prior win.

## Presentation and evidence

Initial/round serializers and fallback capture expose the visible matrix. Direct `serializeWinEvaluationResult(result, geometry)` callers can request the same viewport mapping; omitting geometry preserves evaluation-local data. Public highlights and
paylines are mapped from evaluation coordinates. Legacy line-local arrays (`symbolsPositions`,
`wildSymbolsPositions`, `pattern`) remain reel-index arrays. Overscan line DTOs additionally carry
`visiblePositions` and `visibleWildPositions`; a line that crosses the viewport boundary has no
complete drawing definition (an empty definition), while its paid amount and visible winning cells
remain available. Configured lines without a complete visible path are omitted from initial drawing
metadata. This does not remove or recalculate their monetary wins.

Coordinate fields are additive under the existing schema version; ordinary artifacts keep their shape and hash. Canonical artifacts retain a visible `screen`, evaluation-local wins, and required `geometry` /
`generatedScreen` evidence on the round and each coordinate-aware step. The same evidence is
captured in persisted session `coordinates`, including initial state and partial captures with
`captureDebugPayloads=false`. Validators reject inconsistent projections, malformed geometry,
missing generated evidence and out-of-domain wins. Builders detach/freeze data; geometry or generated
cell changes affect the internal hash. `PokieJsonRoundArtifactProjector` stays lossless and hash-bearing.
`PublicRoundArtifactProjector` is the explicit viewport projection: it omits debug, provenance and
generated evidence and maps win metadata and multiplier positions. Multiplier values and settled
combined amounts retain their original calculation meaning, even for an off-viewport contribution.

Studio inspectors keep canonical JSON in their advanced audit view and use the public projection
for the player. The standalone player, Studio Play round/initial views and inspectors display partial row coverage independently of wins. Games without a serializer receive the same visible screen and coverage through the shared public capture helper; generated evidence remains internal.
Blueprint save/reload, generated CJS/TS modules and Game Model previews preserve geometry. The JSON
editor owns geometry authoring; the payline form explains evaluation-local rows and preserves the field.
Game Model stop scrubbing adds the visible offset rather than reconstructing an unprojected grid.
Public declarations are exposed by root ESM/CJS and browser-safe entry points.
