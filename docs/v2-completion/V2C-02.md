`SessionRuntime` is the portable domain command boundary, composed with `SpinCommandHandler`
for repository ownership and existing settlement/reconciliation. Generated and code-first factories
keep `createSession`; simulation, aggregate/worker execution, replay, Studio scenario searches and
exact enumeration delegate execution. Injected sessions own the math and actual stake.

Repository snapshots carry game/model compatibility, executable schema composition, construction
context, RNG, nominal bet, settled balance and feature state separately from observable screens and
payloads. New runtimes restore supported seeded base/free-game/bet-mode compositions from serialized
records. Live-only engines reject cache loss explicitly. Detached records and results prevent caller
mutation without save. Commands and nested state are checked before math, wallet or recovery writes.
Operational failures retain the primary cause and use existing compensation without claiming
cross-store atomicity. Durable game state alone does not preserve in-memory wallet/retry stores or
Studio's registry. Support and extension guidance is maintained in `game-session.md`,
`serialization.md`, `game-packages.md` and `extension-points.md`.
