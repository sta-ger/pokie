# V2C-19 — Reachability, termination and state invariants

Immutable brief: `sha256:c6bf36b1e24eda0153f57c660a9c625e0bbb22b3c7bcbf8fde11a534478f3fb0`.
Implementation base: `c06e7df9e01c49addca5c2637dc023f9d7509329`.

The asynchronous `AdvancedModelValidator` checks finite transition declarations
and Blueprint declarations. `AdvancedModelSourceValidator` uses the existing
Blueprint/package/PAR/canonical WASM definition readers. Synchronous structural
validators, extraction, generation, PAR conversion and saving remain separate.
The generated root barrel exports the analysis API; filesystem acquisition and
cooperative Node scheduling stay off the browser runtime entrypoint.

The report separates structural validity, declared-model verdict, executable
fidelity, supported checks, assumptions, limitations, work, limits and terminal
status. `valid` on older reports is a contract result. It is not an advanced
safety certificate. No payout cap, session migration, durable validation job or
new top-level CLI command is introduced.

## Analysis boundary

| Source or mechanic | Supported analysis and boundary |
| --- | --- |
| Literal/exact/positive-weight reel support | Circular generated windows, evaluated geometry, actual payout evaluators and executable modes. Zero mass is excluded using the authored weight, without rounding tiny positive weights. Whole-sequence alternatives are retained throughout a logical round. |
| Free games | Actual free-game handler accounting plus additive-retrigger rank witness. Termination means **all paths under supported nondeterministic entropy**; repeatable grants disprove this property without claiming positive-probability or almost-sure nontermination. Remaining counts may repeat while cumulative counters grow. |
| Built-in respins / HoldAndWin | Actual handlers: lifetime `maxRespins` consumption; finite lock progress before reset. Declared transition tables can describe uncapped reset cycles and retain their entry prefix/cycle. |
| Cascade | Actual resolver, evaluator and refill transforms. A configured bound rejection is recorded as a failed transition, never as successful ordinary settlement. Analyzer frontier/depth exhaustion is instead inconclusive. |
| Collection | Actual currency-denominated accumulation, cap and zero/subtract reset. Reachable entry values are closed across paid entries. An unclosed large floating-point value region consumes the analysis budget and remains unknown. |
| Weighted bonus | Actual paid-entry selection/completion handler, identity/context/state validation, duration, zero-weight and zero-duration cases, payouts and completion conservation. |
| Modifiers / accumulating jackpots | Actual initial-logical-round handlers are exercised. Persistent modifier/pool state beyond that round remains explicitly unknown; it is not silently discarded in a lifetime proof. Unsupported compositions retain structural diagnostics. |
| Money / max win | Every available fractional bet and executable mode, charged entry stake, zero-stake continuations, executable-state schema and completed-round conservation. Declared max wins retain currency/bet-multiple units and paid-entry/logical-round scope. Declarations are checked, not enforced as runtime caps. |
| Custom package descriptor | Declared data only. Complete extraction, a generated source label, a codec or package-contract success does not establish executable fidelity. Missing max-win policies remain unknown; unsupported ancestor fields prevent filling runtime defaults. No custom session is created or advanced. |
| PAR / canonical WASM | Imported/canonical declarations only, retaining conversion, inventory and sampling limitations. No executable-fidelity certificate. |
| Legacy packages / outcome libraries / Stake | Useful structural diagnostics; the unavailable generating transition model remains unknown. |

Numeric assumptions are explicit: JavaScript binary64, an initially funded
wallet equal to the charged entry stake, declared feature/pool initial state and
one logical round per paid entry. Lifetime wallet growth and cumulative counter
overflow are not proved safe. Collection entry-value closure is independent of
wallet amount and counters under these assumptions. Supported entropy is an
abstraction; no particular seeded PRNG trajectory is claimed to repeat forever.
Analysis uses isolated built-in runtime handlers with enumerated entropy, not
caller-owned sessions or a separate payout engine.

Limits are positive safe integers (maximum 10,000,000) for input nodes, outcome
expansion, replay states, transitions, depth, retained evidence and yield
frequency. Traversal and preprocessing yield cooperatively. Invalid limits are
caller errors. Budget/depth exhaustion and cancellation never imply a pass;
already retained counterexamples remain visible alongside unresolved checks.
Synchronous custom JavaScript, descriptor promises and filesystem/format readers
are not a general sandbox: cancellation is cooperative and acquisition must
settle before owned cleanup can finish. Cleanup failure remains observable.

## Workflow and publication

`pokie validate SOURCE` prints structural errors/warnings and the shared advanced
report; `--format json` retains the report verbatim. Exit 0 means the supported
analysis completed within its assumptions, 1 means a contract error or declared
counterexample, 2 means inconclusive/unsupported analysis, 3 means an advanced
source/operational failure after structural success, and 130 means cancellation
after structural success. `--deep` retains its outcome-library meaning.
Output/write errors remain command failures. `--out` requires an unused path
outside a source directory; complete labelled JSON is staged and linked without
replacing source files, aliases or prior reports. Temporary staging is cleaned
on both success and failure.

Definition comparison retains advanced outcomes, witnesses, assumptions, limits
and unknown results in validation changes. Mathematical, representation and
statistical comparison retain their established distinctions. The existing
opt-in `diff --ci` policy returns 2 for unresolved/invalid analysis, 1 for a
supported mathematical change, and 0 for supported nonmathematical differences.
An unchanged but unsupported analysis cannot become an empty safe CI result.

Studio draft and saved-project validation use the same report. Blueprint and
Overview display errors and warnings together, unknown checks, paths, evidence,
limits and assumptions. Validation/comparison are read-only. Request abort,
server shutdown, retry and source/project/revision freshness retain their own
lifecycles. Explicit Save/Apply and current source checks still own authored
changes. Structural validators remain the save/build compatibility gates;
advanced analysis is an explicit diagnostic/CI operation, not a hidden recursive
prerequisite of every extraction or artifact conversion. A completed report is
bound to the current draft and cannot authorize a later revision.

A charged entry is expected to execute with a wallet initially equal to its
advertised stake. If a discounted mode's wrapped base guard instead refuses
that entry, analysis retains the blocked before/after state and funding values;
it does not count a no-op as a charged, settled spin. Completion-total comparison
allows only 32 binary64 epsilon units relative to the actual amounts and bet;
there is no fixed currency floor that could hide a `1e-7` stake. Explicit
transition-table accounting remains exact.

`inputNodes` also charges string characters and a conservative structural/config
comparison bound; `transitions` includes isolated runtime reconstruction work.
This prevents large declarations or replay setup from escaping the traversal
budget merely because they have few top-level fields. Limits can be raised
explicitly; a conservative work estimate exhausting a limit remains unknown.

Blueprint source acquisition is bounded before JSON parsing (default 400,000
bytes; source validation derives this conservative byte limit from the input
budget). A bounded descriptor read also handles a file growing after its size
check. The file descriptor is always closed. A source budget rejection records
unknown structural validity, rather than inventing a structural pass.

Explicit Studio validation does not run the legacy synchronous feasibility check
before analysis. Drafts whose structural validity is still unknown have a distinct
`inconclusive` view; a successful result is not cached for creation. Saved-project
validation also acquires its advanced report before entering structural adapters.
The CLI skips structural parsing when bounded acquisition did not finish, returns
2 for that budget outcome and 130 for cancellation. Existing synchronous save,
build, preview and PAR validators retain their separate compatibility contract.
Primitive RNG calls and support samplers are assumed to return; mechanic proofs
do not claim worst-case termination of rejection sampling or arbitrary RNG code.

Acquired declarations retain their reader model revision in the report. Saved
Blueprint validation rereads through the bounded reader and compares that
revision before returning success; a concurrent source replacement returns a
409 retry response. Opaque packages and outcome artifacts still receive their
independent structural/contract diagnostics even when model analysis is unsupported.

The separate `outcomeCells` limit (default 100,000) is charged before strip/window,
probe-screen and retained snapshot allocations. Counting only outcome tuples
would permit a large row window to multiply storage beyond that limit. Singleton
entropy choices do not create redundant replay branches. If a witness cannot be
retained within its budget, the established diagnostic remains a violation with
an explicit retention-interrupted marker; unresolved checks remain unknown.

All-path termination means normal feature settlement. Runtime execution/delivery
limits and numeric guards that retain or reject an unfinished feature do not prove
settlement. Free-game witnesses use the declared remaining-count recurrence and
an actual funded entry/retrigger prefix, recording default-mode stake and credits;
no equality of cumulative cursor/sum counters or infinite seeded execution is
claimed. Numeric behavior outside that prefix remains unknown. Rejected runtime
transitions never receive a passing normal-settlement check.
