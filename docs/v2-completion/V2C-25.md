   Studio HTTP callers. Its separate `apply(candidate, currentRequest)` commits authored Blueprint,
   canonical lossless PAR, or declared TS parameters/contract metadata. Artifact `publish`/`--out`/Studio
   save retain new/empty destination guards. The public workflow table runs all six native types through
   the engine and registered CLI, reopens and measures their outputs, and exercises authored apply on
   Blueprint/PAR/custom executable TS. Custom executable identity/code, PAR non-paytable model fields,
   native outcome IDs/artifacts/untouched modes and uint64 Stake weights remain intact. Generated outputs
   survive candidate discard. PAR optimizer ZIP timestamps are stable across CLI preview/apply processes.
2. Studio renders targets, units, population, tolerance, held-out estimate/CI/confidence/actual count,
   exact versus sampled verdict, tunables, locks, protected files, constraint checks, precision, parameter
   changes and available shared-authority definition changes. Native changes remain native values.
   Apply/save bind the current normalized request to the retained candidate receipt. Source/candidate
   bytes, model/contract and executable dependency identity are rechecked. Authored apply validates a
   detached same-type output before mutation; multi-file commit rolls back owned writes, preserves
   competing edits, and retains failed staging cleanup ownership. Repeated apply consumes the receipt.
   Studio resets Play, reloads the runtime, and records a consumed-preview marker without replacing the
   mathematical verdict/evidence; a failed marker write explicitly reports that source was applied.
3. Public regressions reattach an active server job after real observations, cancel search/assessment

   after worker observations also drains and permits retry. Prerequisite worker/publication/durable-job
   tests are reused. Browser reload and server restart remain different: JSON retains evidence, not
   resumable optimization checkpoints or apply authority. Canonical jobs survive alias routing. Project
   transition/shutdown cancels and drains executions and retained candidates. Published artifacts remain
   independent; unsupported resume is never claimed.
4. The six-type public engine/registered-CLI table and mounted dashboard capability/support table cover
   blueprint, parWorkbook, tsPackage, outcomeLibrary, stakeAdapter and wasm. Tuning requires the existing
   type-specific declaration/native authority, not a generic runtime/build capability. Existing negative
   adapter/CLI/Studio cases retain opaque/stale TS executable sentinels, unsupported WASM/PAR/scope/metric
   rejection and absent preparation/output guarantees. Build remains the conversion boundary; no
   top-level export or new unsupported tuning permission was introduced.
