Acceptance ledger:

1. `InteropNumericFidelity` reopens actual ExcelJS workbooks across the existing
   mechanic/composition/modifier/bounded/weighted-bonus catalogues and win evaluators.
   It checks represented and applicable full-content hashes, resolved projection,
   seeded runtime terminal results and restored continuations with fractional bets,
   weighted identities/order/zero mass and exact reels. Empty optional arrays/strings
   canonicalize to absence; empty paytable maps now use symbol-only rows. Geometry
   remains explicitly unsupported before publication; capped/unknown package policy
   rejection remains unchanged. Mechanics extra cells, invalid declarations and
   formula cached values prevent lossless certification. Existing weighted-sequence,
   importer, mapper, Studio draft and optimizer regressions remain required.
2. Exact Stake payload interchange retains each original CSV weight and all payload
   bytes when native safe-integer totals would be exceeded. `exactSource` is distinct
   from numeric `modes`; durable import produces a Stake adapter, never a rescaled
   numeric Outcome Library. Reopen/build/direct exact export and real command adapters
   retain the 2^64 distribution, nonzero known-answer metrics and aggregate deltas.
   Native optimizer output reuses its complete captured inventory and archived input
   provenance without promoting an old library hash. Native library/bundle sampling
   restrictions remain; numeric moments are binary64 approximations, separate from
   exact weight accounting and capped decimal probability strings.
3. Independent cases cover CSV/book/direct numeric IDs, raw CSV/book payouts, UInt64
   weights, blanks and unmatched books IDs. IDs/raw payouts are nonnegative safe
   integers through 9007199254740991; positive individual weights end at
   18446744073709551615, while aggregate totals can exceed UInt64 on the exact path.
   Numeric library exporters reject unsafe Number weights. Fractional native
   stakes/ratios and exact cost reversal remain separate contracts.
4. Existing atomic publication/ownership mechanisms are reused for the exact payload,
   including captured-byte revalidation and new/empty destinations. Tests cover
   occupied output, cancellation, owned write failure, competing claimants and retry.
   Workbook custom writers now serialize into owned staging; late cancellation after
   exclusive linking rolls back only the owned inode. Prior non-lossless Blueprint
   sidecars cannot be upgraded by re-export. Existing pair/intermediate/Studio job
   rollback tests are retained. Public docs distinguish direct recognized-export
   rebuild from canonical new/empty conversions and disclose unsupported/lossy fields.
