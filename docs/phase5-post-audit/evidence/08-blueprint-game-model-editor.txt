BlueprintJsonPanel.tsx (full file, 20 lines):

    import {Button, Textarea} from "@mantine/core";
    import {useRef} from "react";
    import {ErrorState} from "../common/ErrorState";
    import {QuickActions} from "../common/QuickActions";

    export function BlueprintJsonPanel({jsonText, jsonError, onApply}: {jsonText: string; jsonError?: string; onApply: (text: string) => void}) {
        const textareaRef = useRef<HTMLTextAreaElement>(null);

        return (
            <div>
                <Textarea ref={textareaRef} label="Blueprint JSON" rows={24} defaultValue={jsonText} spellCheck={false} style={{fontFamily: "monospace"}} />
                <QuickActions>
                    <Button variant="default" onClick={() => onApply(textareaRef.current?.value ?? "")}>
                        Apply JSON
                    </Button>
                </QuickActions>
                {jsonError && <ErrorState message={jsonError} />}
            </div>
        );
    }

The <Textarea> is uncontrolled (defaultValue, not value) and read only via textareaRef when "Apply JSON"
is clicked. Typing updates only the DOM node; it never reaches editor.state until Apply is clicked.

Dirty-tracking (BlueprintEditorPage.tsx:240-268) is entirely revision-based: cleanRevisionRef holds the
last "safe" revision, and `dirty = editor.state.revision !== cleanRevisionRef.current` (line ~279).
editor.state.revision only advances on a *committed* mutation — a Form field edit (mutate), New, Load, or
a successful "Apply JSON" (comment at line 369: "A form edit, New, Load, and a successful JSON Apply all
bump `revision`"). Raw, unapplied JSON-textarea keystrokes never bump revision, so none of the editor's
unsaved-work protections (isDirty flag, navigation blocker, beforeunload guard) ever see them.

Switching `mode` away from "json" unmounts BlueprintJsonPanel (React discards the DOM node, including any
uncommitted keystrokes, permanently) with no guard/dirty-check/confirm on SegmentedControl's onChange.

Contrast: GameModelTab.tsx / GameModelSections.tsx's per-section Form editors and the round-trip
serialization (serializeGameBlueprint.ts:18-21 preserves unrecognized keys; blueprintEditorState.ts
withFieldUpdate mutates only known fields) all work as documented — this is not a general round-trip
problem, it is specific to the uncontrolled JSON textarea's interaction with the mode toggle.

No doc comment anywhere in BlueprintEditorPage.tsx, BlueprintJsonPanel.tsx, docs/studio-frontend.md, or
docs/studio-phase2-inventory.md acknowledges this as deliberate.

CLASSIFICATION: CONFIRMED P2
=============================
Real, reproduced, zero-warning loss of in-progress (never-applied) work when a user types in the JSON
textarea and then switches the mode toggle (or navigates away) without clicking "Apply JSON". Kept at P2,
not P0/P1: it does not corrupt or clobber anything already saved to disk, requires a specific interaction
(type in JSON mode, then switch away without applying), and every other editing surface in this same
editor (Form fields, GameModelTab's per-section editors) captures edits immediately and is unaffected.
Not P3: it is real, non-cosmetic loss of a user's hand-typed work with no warning at all, in a surface
explicitly meant for raw Blueprint JSON editing.
