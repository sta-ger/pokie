Before this step's fix, GameModelSections.tsx (Studio's own canonical, post-creation Game Model tab --
Design Blueprint -> open project -> Game Model) rendered Mechanics/Limits read-only, with no Edit
action and no explanation, alongside 6 other sections that DO have a real field editor:

  function MechanicsSection(...) { ... }          // read-only render only, no mutate() call anywhere
  <PageSection legend="Mechanics">                 // no action= Edit/Save/Cancel, unlike every other section
      <MechanicsSection section={projection.mechanics} />
  </PageSection>

The only place mechanics.freeGames was actually reachable for an EXISTING project was the standalone
'pokie edit <blueprint>' CLI wizard (cli/wizard/GameBlueprintWizard.ts askMechanics(), invoked from
cli/commands/EditCommand.ts) -- a genuinely separate, competing mutation path outside Studio entirely,
confirmed by reading cli/commands/EditCommand.ts and cli/wizard/GameBlueprintWizard.ts directly.

'Limits' (GameModelLimits: minBet/maxBet) is NOT a stored GameBlueprint field at all -- confirmed by
grepping src/generated/GameBlueprint.ts for 'limits' (zero hits); it is purely derived from Bets &
Modes' own availableBets (src/project/buildGameModelProjection.ts's deriveLimits). Its own read-only
status was already correct; the gap there was that the UI never said so -- it just showed data or
'No bet limits configured.' with no explanation of why there was no Edit button at all.

--- 2. The fix ---

Mechanics (freeGames) is now edited through Game Model itself (FreeGamesFieldset.tsx, wired into
GameModelSections.tsx's existing per-section Edit/Save/Cancel + single-whole-blueprint-write flow --
the exact same architecture PaytableEditor/BetsList already use, not a second, competing editor or
mutation path the way the old, deleted MechanicsEditorTab was). Limits stays read-only, but now says
truthfully, in every state, that it is derived from Bets & Modes' own Available bets.
