# PC-05 capability matrix

This is the acceptance contract for product coherence, frozen after the PC-02,
PC-03, and PC-04 evidence.  The machine-readable artifact vocabulary is
[`artifact-registry.json`](artifact-registry.json).  A dash means the surface
does not expose the operation; it is not evidence that the operation works by
some other route.

| Domain operation / user goal | CLI | Studio | Public docs | Shared contract / defaults | Prerequisite and validation | Diagnostic semantics | Owner |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Create an editable game design | `create` (`--blank`, `--random`, wizard) | Home Design / create | `getting-started.md` | `GameBlueprint`; default output derives from id | valid blueprint required before dependent builds | file conflict: no overwrite; invalid fields are actionable | PC-09 docs/surface sweep |
| Edit a design | `edit` | Design editor | `getting-started.md` | canonical Blueprint JSON | load then validate before save/build | edited source invalidates results | PC-07 Studio-source recovery |
| Recognize/open a project | `inspect`, path-taking commands | Projects / register/open | `docs/README.md`, `game-packages.md` | `ProjectTargetResolver`, `ProjectType` | resolver classifies Blueprint/package/library/Stake/PAR/WASM | name the recognized type and next action; do not leak parser internals | PC-06 diagnostic sweep |
| Exchange a PAR workbook | `par export`, `par import`; `export --to workbook` | PAR import/export panel | `stake-engine-import.md` is not authoritative; PAR docs/examples are | `ParSheetExporter`/`ParSheetImporter`; XLSX | Blueprint → workbook → Blueprint | workbook is exchange-only; say import-before-run | PC-09 docs/surface sweep |
| Build a runnable package | `build --target tsPackage` | Build/Export artifact target | `game-packages.md` | `ArtifactBuilderRegistry`, `BUILD_PRODUCT_MATRIX`; default sibling `tsPackage` | Blueprint; `GameBlueprintValidator`, materialization | unsupported source uses shared matrix diagnostic | PC-06 contract sweep |
| Generate or build an Outcome Library | `build --target outcomeLibrary`, `export --to outcomes` | Outcome Libraries / Build-Export | `outcome-library-bundle.md` | registry-managed prerequisite workflow; native bundle manifest/index/JSONL | Blueprint/package must support exact enumeration; library deep-validation | unsupported generation gives domain reason and alternative; no silent approximate fallback | PC-08 duplication sweep |
| Sample/analyze precomputed outcomes | `sample`, `report`, `diff` | Outcome source overview / sample | `outcome-library-bundle.md`, `stake-engine-standalone.md` | `OUTCOME_SOURCE_*` capabilities | native library can sample; native library and Stake export can analyze/diff | clearly distinguish read-only Stake source from drawable native library | PC-06 diagnostic sweep |
| Export Stake files | `build --target stakeAdapter`, `export --to adapter` | Build/Export and Stake Export | `stake-engine-export.md` | registry plus `StakeEngineExporter` | library, or Blueprint/package via managed compatible library | show prerequisite generation and output conflict, not a second incompatible workflow | PC-08 duplication sweep |
| Import Stake files | `import` | Project registration/open only; no equivalent conversion action | `stake-engine-import.md` | `StakeEngineImporter` reconstructs Outcome Library | POKIE-produced export needs `pokie-manifest.json`; generic Stake is analysis-only | incompatible library input must name its type, supported imports and recovery | PC-06 (PC-05-CLI-02/04) |
| Validate artifacts | `validate`; `outcomelibrary validate`; certification verify | Blueprint check, Outcome/Stake export validate, certification source validate | artifact-specific docs | resolver plus validators; `--deep` applies to libraries | target-specific validation only | state what was checked and what is not checked (notably WASM/runtime) | PC-06 contract sweep |
| Run/play a game | `serve`, `client`, `dev` | Play | `game-packages.md`, `pregenerated-runtime.md` | `RUNTIME_EXECUTE_CAPABILITY` or native outcome-source sampling | runnable package or native Outcome Library, mode when required | package execution versus pre-generated draw must remain explicit | PC-08 Studio parity |
| Simulate | `sim --out` | Simulation | `getting-started.md`, `pregenerated-runtime.md` | package runtime or `OUTCOME_SOURCE_SAMPLE_CAPABILITY`; report JSON | package or native library; seeded native simulation is replayable | reject missing native-library seed/mode when exact replay is promised | PC-06 contract sweep |
| Render/compare reports | `report`, `diff` | Simulation results only | `getting-started.md`, `stake-engine-standalone.md` | simulation-report parser / outcome-source analyzer | report JSON or analyzable native/Stake source | presentation output is analysis, never a project artifact | PC-08 Studio parity |
| Replay a result | `replay --out` | Replay (seed, artifact, session spin, simulation sources) | `pregenerated-runtime.md`, `round-artifacts.md` | exact native descriptor versus best-effort package replay | library id/hash/mode/seed/round must match for exact result | mismatch must identify stale/incompatible provenance; package replay says best effort | PC-06 provenance sweep |
| Certify an Outcome Library | `certification build`, `certification verify` | Certification build/inspect/export | `certification-evidence-bundle.md` | `CertificationEvidenceBundle*` | native library and config; verify also requires live source | build/source validation differs from independent post-build verification | PC-08 Studio parity (verify gap) |
| Prove fairness | `fairness seed-commit/commit/reveal/verify` | Provably Fair configure/generate/verify | `provably-fair.md` | commitment/proof validators and verifier | private seed file, native library, mode; matching commitment/source for verify | never disclose private seed; mismatch fails closed | PC-06 provenance sweep |
| Deploy an external format | no first-class public CLI command | Export/Deploy | `external-adapter-sdk.md` | `ExternalDeploymentService` + registered target | native library and target capability | stage-specific diagnostic; private RGS integration is not implied | PC-08 Studio/public parity decision |
| Generate/inspect reel strips | `reel generate` | Blueprint reel tools | `reel-strip-generation.md` | `resolveReelStripGeneration` | Blueprint constraints | generation failure is design validation, not runtime failure | PC-09 docs/surface sweep |
| Assess WASM compatibility | `inspect` resolves compatible sidecar; no `wasm` command | register/open/inspect metadata only | `wasm-compatibility-boundary.md` | `WasmProjectTargetAdapter`, manifest validator | compatible `.wasm` + sidecar manifest | inspection-only; explicitly reject build/run/simulate/validate-logic promises | PC-09 unsupported-boundary sweep |

## Closure ledger: mismatches and duplicate paths

| ID | Classification | Evidence / architecture fact | Owning remediation or sweep | Completion condition |
| --- | --- | --- | --- | --- |
| PC-05-CLI-01 | false prerequisite | PC-02: `inspect` says Blueprint must build before simulate; direct Blueprint `sim` succeeds | PC-06 diagnostic sweep | one canonical capability decision; inspect/help/runtime agree and test both source paths |
| PC-05-CLI-02 | incompatible-input diagnostic | PC-02: Outcome Library passed to `import` yields only `stakeengine-import-index-missing` | PC-06 diagnostic sweep | error names supplied kind, accepted input kinds, and recovery without exposing parser file names |
| PC-05-CLI-03 | duplicated command rendering | PC-02: create’s suggested Build command does not quote a spaced path | PC-06 diagnostic/output sweep | every generated command is shell-safe for the actual supplied path; regression includes spaces |
| PC-05-CLI-04 | duplicated public grammar | PC-02: `import --help` advertises `--format`, delegated handler rejects it | PC-06 CLI grammar sweep | one parser/help contract; advertised option is accepted or removed everywhere |
| PC-05-STUDIO-01 | import replacement/recovery | PC-03 frozen P2: saved-design selection can replace editable starter with invalid/blank state without explanatory import error | PC-07 Studio-source recovery | selection validates before replacement or retains prior design; visible recovery explains outcome |
| PC-05-STUDIO-02 | capability asymmetry | Studio can build certification but CLI alone verifies an already-built bundle against source | PC-08 Studio parity decision | explicitly ship Studio verification or label/route the external CLI handoff; docs/matrix agree |
| PC-05-DUP-01 | artifact conversion duplication | `build`, `export`, specialised `par`, and Stake actions overlap | PC-08 conversion-entry-point sweep | each user goal has one canonical route; aliases delegate with identical defaults, validation and diagnostics |
| PC-05-DUP-02 | runtime/outcome-source duplication | package runtime and native outcome source share sim/replay/serve nouns with different guarantees | PC-06 provenance sweep | every surface labels execution vs pre-generated selection and exact vs best-effort replay |
| PC-05-DUP-03 | validation duplication | CLI and Studio expose different subsets of Blueprint/library/Stake/certification checks | PC-08 Studio parity decision | capability matrix is reflected in controls, disabled states and explicit CLI handoffs |
| PC-05-DOC-01 | documentation drift risk | `ProjectPresentation` and public docs can state prerequisites independently | PC-09 docs/surface sweep | docs derive/verify against shared capability contract and deliberate unsupported boundaries |

The owner labels are future immutable steps, not product changes made by PC-05.
